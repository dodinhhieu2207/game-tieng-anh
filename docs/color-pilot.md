# Color Pilot — Unit 2 Lesson 1

Replaces Colour It's presentation on the existing `colour` route and `2/1/colour` progress key. Uses the exact existing five-color vocabulary: red, green, blue, black and white. A color droplet is the prompt; two neutrally colored word labels are possible destinations. No target name is read automatically. Hear a hint reads only the color word. The child steers up/down, drags, or uses arrow keys to intercept the matching word. The same fair motor-miss, pause, reduced-motion and best-score rules apply as Toy Delivery.

Implementation uses one configurable pilot engine in shared/toy-delivery.js. shared/color-pilot.js supplies vocabulary, new picture/audio paths, the approved Unit 2 elephant, target-color styling, completion title and the existing Unit 2 parent route. Unit 3 defaults retain their original toy images, speech and route. No duplicate scoring or storage system is added.

New art: five identically shaped colored drops and palette reward from an original imagegen atlas, plus a separate sky/school landing background. Shared glossy controls, VFX and original SFX remain from Toy Delivery. A correct delivery reveals the color, plays its standalone Higgs word and celebrates briefly. Labels remain neutral, preventing color-coded answer leakage.

Five new standalone MP3s are generated by tools/build_color_pilot_audio.py using the existing offline Higgs V3 model and the exact existing Unit 2 Belinda reference. Audio manifest records reference hash, output hashes and automated transcript verification. Existing Unit 2 catalogue and voices are preserved. Automated transcription verifies words, not child learning or human approval of the new takes.

Validation: tests/color-pilot.spec.cjs covers every new audio clip, neutral labels, wrong choice, hints, five widths, correct progress key, Unit 3 defaults and reduced motion. Existing Toy Delivery integration checks run after the engine configuration change. Navigation tests verify all original activity routes remain mapped.
